# JOE Store setup  ## Current hosting status  The Vercel project is `joes-store`. Its generated project hostname is `https://joes-store-jomohamads-projects.vercel.app` (the latest production deployment also has a deployment-specific URL). Vercel's project metadata lists the generated hostname; use the project hostname for the canonical production URL.  The requested `joe_store.vercel.app` cannot be used: underscores are not valid in a web hostname, and Vercel rejects it as an invalid domain. The closest spelling, `joe-store.vercel.app`, is already assigned to another Vercel team, so this project cannot claim it. The production `NEXT_PUBLIC_SITE_URL` variable has been set to the generated project hostname, and the production redeploy is ready. Both the generated project hostname and the redeploy URL return HTTP 200.  If a shorter custom hostname is needed, choose a valid domain that the account owns or can register, add it to the `joes-store` project in Vercel, wait for Vercel to verify its DNS, and then update production `NEXT_PUBLIC_SITE_URL`. Update Supabase Auth's Site URL and redirect allow-list and the passkey relying-party ID/origin to match that final hostname. Do not use `joe-store.vercel.app` unless its current Vercel owner releases it or transfers it to this team.  ## Supabase project  The app uses the existing Supabase project JOE-s-store (ljmgvyvbvinrcdmxptrx). Database changes for newsletter consent, profile fields, coupons, promotional banners, and sales are in supabase/migrations.  Set local and Vercel variables from .env.example. Never expose a service-role key through a NEXT_PUBLIC variable.  ## Google sign-in  1. Create a Google OAuth web client in Google Cloud Console. 2. Add https://ljmgvyvbvinrcdmxptrx.supabase.co/auth/v1/callback as an authorized redirect URI. 3. In Supabase Dashboard ΓåÆ Authentication ΓåÆ Sign In / Providers ΓåÆ Google, enable Google and enter the OAuth client ID and secret. 4. In Authentication ΓåÆ URL Configuration, allow the production origin and /auth/callback. Add http://localhost:3000/auth/callback for local work. 5. Test on the exact production hostname.  Google OAuth requires the Google-issued client ID and secret; they are not present in this repository.  ## Passkeys  The app opts into Supabase WebAuthn passkeys. Supabase Auth must also have passkeys enabled. Set the relying-party ID to the production hostname without a scheme or path, and add its exact HTTPS origin. Local development uses localhost and http://localhost:3000. 127.0.0.1 is a different origin and will be rejected. Production passkeys require HTTPS.  ## Auth email and SMTP  Branded templates are in supabase/templates. In Supabase Dashboard ΓåÆ Authentication ΓåÆ Email Templates, use the matching HTML and subject. Configure an SMTP provider under Authentication ΓåÆ SMTP Settings and verify its sender domain. Keep SMTP credentials in Supabase only.  SMTP provider credentials are not in the repository; email delivery still needs dashboard configuration.  ## Newsletter campaigns  Newsletter uses consent and double opt-in. Admin campaigns use Resend. Add RESEND_API_KEY, RESEND_FROM_EMAIL, and production NEXT_PUBLIC_SITE_URL to Vercel server environment variables. Verify the sender domain first, then test with an internal confirmed address before sending to customers.  ## Admin access  The admin link is rendered only when the signed-in user's UUID exists in public.admin_users. The project currently has no admin membership. An authorized owner must add the intended Auth UUID in Supabase; do not grant by email alone.  ## Phone verification  Phone verification uses Supabase Auth SMS OTP. Configure an SMS provider in Supabase Authentication ΓåÆ SMS. WhatsApp and contact fields are stored in profiles; only the Auth phone number receives OTP verification.  ## Deployment  The Vercel production `NEXT_PUBLIC_SITE_URL` is set to `https://joes-store-jomohamads-projects.vercel.app`, and the latest production deployment is ready. In Supabase Authentication ΓåÆ URL Configuration, set Site URL to the chosen canonical origin and allow that origin plus `/auth/callback`. Passkeys bind to the hostname, so use one canonical domain consistently. If you later attach a different domain, update Vercel, Supabase Auth, OAuth redirect settings, and the passkey RP ID together.
